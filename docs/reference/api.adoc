= API Reference

Complete reference for Vectory's public API.

== Format Classes

=== Vectory::Image

Base class for all image types.

[source,ruby]
----
# Factory method (auto-detects format)
image = Vectory::Image.from_path("diagram.eps")
----

**Methods**:

* `Vectory::Image.from_path(path)` - Load from file path
* `Vectory::Image.from_content(content)` - Load from content string
* `Vectory::Image.from_datauri(uri)` - Load from data URI

=== Vectory::Vector

Abstract base class for vector formats. Inherits from `Vectory::Image`.

[source,ruby]
----
# Conversion methods available on all vector formats
vector.to_eps
vector.to_ps
vector.to_emf
vector.to_svg
vector.to_pdf
----

=== Vectory::Eps

Encapsulated PostScript format.

[source,ruby]
----
# Load EPS
eps = Vectory::Eps.from_path("diagram.eps")

# Convert to other formats
svg = eps.to_svg
pdf = eps.to_pdf
ps = eps.to_ps
----

**Key Methods**:

* `Vectory::Eps.from_path(path)` - Load from file
* `Vectory::Eps.from_content(content)` - Load from string
* `Vectory::Eps.from_datauri(uri)` - Load from data URI
* `#dimensions` - Get [width, height] in points
* `#to_svg` - Convert to SVG
* `#to_pdf` - Convert to PDF
* `#to_eps` - Return self
* `#to_ps` - Convert to PS
* `#to_emf` - Convert to EMF (via SVG)
* `#write(path = nil)` - Write to file
* `#content` - Raw file content
* `#initial_path` - Original file location
* `#path` - Current write location

=== Vectory::Ps

PostScript format. Same API as `Vectory::Eps`.

[source,ruby]
----
ps = Vectory::Ps.from_path("document.ps")
svg = ps.to_svg
----

=== Vectory::Svg

Scalable Vector Graphics format.

[source,ruby]
----
svg = Vectory::Svg.from_path("drawing.svg")
eps = svg.to_eps
pdf = svg.to_pdf
----

=== Vectory::Emf

Enhanced Metafile format.

[source,ruby]
----
emf = Vectory::Emf.from_path("chart.emf")
svg = emf.to_svg
----

Uses the emfsvg gem for conversion.

=== Vectory::Pdf

PDF format (used internally as intermediate format).

[source,ruby]
----
pdf = Vectory::Pdf.from_path("document.pdf")
svg = pdf.to_svg
----

## Factory Methods

All format classes support these factory methods:

### from_path

Load from file path:

[source,ruby]
----
eps = Vectory::Eps.from_path("diagram.eps")
----

### from_content

Load from content string:

[source,ruby]
----
content = File.read("diagram.eps")
eps = Vectory::Eps.from_content(content)
----

### from_datauri

Load from data URI:

[source,ruby]
----
uri = "data:image/svg+xml;base64,PHN2Zy..."
svg = Vectory::Svg.from_datauri(uri)
----

### from_node

Load from XML node (Metanorma integration):

[source,ruby]
----
# Used internally by Metanorma
svg = Vectory::Svg.from_node(xml_node)
----

## Conversion Methods

All format classes support conversion to any other format:

[source,ruby]
----
# Convert EPS to SVG
svg = Vectory::Eps.from_path("diagram.eps").to_svg

# Convert SVG to EPS
eps = Vectory::Svg.from_path("diagram.svg").to_eps

# Convert EMF to SVG
svg = Vectory::Emf.from_path("chart.emf").to_svg
----

## Properties

### content

Raw file content as string:

[source,ruby]
----
eps = Vectory::Eps.from_path("diagram.eps")
raw = eps.content
----

### initial_path

Original file location (read-only):

[source,ruby]
----
eps = Vectory::Eps.from_path("diagram.eps")
puts eps.initial_path  # => "diagram.eps"
----

### path

Current file location (raises error if not written):

[source,ruby]
----
eps = Vectory::Eps.from_path("diagram.eps")

# WRONG: raises error
puts eps.path  # => NotWrittenToDiskError

# CORRECT: write first
eps.write("output.eps")
puts eps.path  # => "output.eps"
----

### dimensions

Image dimensions as [width, height]:

[source,ruby]
----
eps = Vectory::Eps.from_path("diagram.eps")
width, height = eps.dimensions
puts "Size: #{width}x#{height}"
----

## Methods

### write

Write image to file:

[source,ruby]
----
# Write to specific path
svg.write("output.svg")

# Write to temp directory
svg.write
----

Returns the path to the written file.

## Usage Examples

=== Basic Conversion

[source,ruby]
----
require 'vectory'

# EPS to SVG
svg = Vectory::Eps.from_path("diagram.eps").to_svg
svg.write("diagram.svg")
----

=== Batch Processing

[source,ruby]
----
Dir["diagrams/*.eps"].each do |eps_file|
  svg = Vectory::Eps.from_path(eps_file).to_svg
  svg.write(eps_file.sub(".eps", ".svg"))
end
----

=== Error Handling

[source,ruby]
----
begin
  svg = Vectory::Eps.from_path("diagram.eps").to_svg
rescue Vectory::InkscapeNotFoundError => e
  puts "Inkscape not found: #{e.message}"
rescue Vectory::ConversionError => e
  puts "Conversion failed: #{e.message}"
end
----

=== Dimension query

[source,ruby]
----
eps = Vectory::Eps.from_path("diagram.eps")
width, height = eps.dimensions
puts "Dimensions: #{width}x#{height}"
----

== SVG mapping

Integrates SVG content into XML documents with ID disambiguation for multi-document scenarios.

=== Vectory::SvgMapping

Processes XML documents containing `<svgmap>` elements, extracting and integrating SVG content.

[source,ruby]
----
# Basic usage
xml_string = Vectory::SvgMapping.from_path("doc.xml").to_xml

# With ID suffix for cross-document uniqueness
mapping = Vectory::SvgMapping.new(doc, "", id_suffix: "_ISO_17301-1_2016")
xml_string = mapping.call.to_xml
----

**Factory methods**:

* `Vectory::SvgMapping.from_path(path)` - Load from file path
* `Vectory::SvgMapping.from_xml(xml)` - Load from XML string
* `Vectory::SvgMapping.new(doc, local_directory, id_suffix: nil)` - Direct instantiation

**Parameters**:

* `doc` - Nokogiri XML Document containing svgmap elements
* `local_directory` - Directory for resolving relative file paths
* `id_suffix` - Optional suffix for cross-document ID uniqueness (e.g., "_ISO_17301-1_2016")

**Methods**:

* `#call` - Process all svgmap elements, returns processed document
* `#to_xml` - Process and return XML string

=== Vectory::SvgDocument

Represents an SVG document and handles ID suffixing for uniqueness.

[source,ruby]
----
# Create from SVG content
svg_doc = Vectory::SvgDocument.new(svg_content)

# Apply both ID suffix and index suffix
svg_doc.namespace(index, links, xpath_to_remove, id_suffix: "_ISO_17301-1_2016")
result = svg_doc.content
----

**Constructor**:

* `Vectory::SvgDocument.new(content)` - Create from SVG XML string

**Methods**:

* `namespace(index_suffix, links, xpath_to_remove, id_suffix: nil)` - Apply transformations
** `index_suffix` - Position-based suffix (0, 1, 2...) formatted as 9-digit zero-padded
** `links` - Hash mapping hrefs to targets
** `xpath_to_remove` - XPath for elements to remove (processing instructions)
** `id_suffix` - Optional identity-based suffix for cross-document uniqueness

* `content` - Returns processed SVG as XML string
* `remap_links(map)` - Remap internal links
* `apply_id_suffix(id_suffix)` - Apply ID suffix
* `apply_index_suffix(index)` - Apply index suffix

=== ID Suffixing

SVG IDs are suffixed in two stages:

[source]
----
# Stage 1: ID suffix (cross-document uniqueness)
fig1 → fig1_ISO_17301-1_2016

# Stage 2: Index suffix (multi-svgmap uniqueness)
fig1_ISO_17301-1_2016 → fig1_ISO_17301-1_2016_000000000
----

* **ID suffix** (`id_suffix` parameter): Derived from document/container identity. Optional.
* **Index suffix** (`index_suffix` parameter): Zero-padded position (0, 1, 2... → _000000000, _000000001). Automatically applied.

== Serialized SVG transforms

All methods consume XML strings and return a new XML string. The input DOM is
never shared with the result. These content transforms do not render PNG images.

* `SvgClassSuffixer.rewrite(content, suffix)` updates XML class lists and CSS class
  selectors using Crass, including escaped identifiers and nested selector rules.
  Reapplying the same suffix is idempotent.
* `SvgNamespaceBinding.rewrite(content, bind: {}, unbind: [], remap: {})` binds
  prefix-to-URI declarations, unbinds unused prefixes, and remaps URIs to target
  prefixes. An empty or nil prefix means the default namespace. Expanded names
  are preserved; default namespaces never qualify unprefixed attributes.
  Conflicting bindings, used unbinds and identity-changing default remaps raise
  `ArgumentError`. Malformed, rootless or non-SVG input also raises `ArgumentError`.
* `SvgSubtreeGraft.replace_root_content(host_content, processed_content)` preserves
  the host document/root metadata and replaces only the ordered root children,
  including text, comments, CDATA and processing instructions. Invalid input
  raises `Vectory::ParsingError`, identifying `host_content` or `processed_content`.
  Grafts decode each input's XML encoding and return UTF-8, updating an existing
  encoding declaration while preserving document content and envelope order.

`SvgTransform` factories return named immutable steps:

* `graft_into(host_content:)` validates and captures the host at construction.
* `disambiguate(index:, duplicate_ids:)` delegates to `SvgIdDisambiguator` with a
  deeply copied collision map and `_inject_<index>` suffix.
* `suffix_classes(index:)` uses that same suffix for classes.
* `bind_namespaces(bind: {}, unbind: [], remap: {})` uses the namespace contract above.

Compose steps with `>>`. `SvgTransformPipeline#steps` exposes stable names and
deeply frozen option snapshots; `#profile` identifies the executable profile.
`#call(content)` returns serialized XML. Exactly three profiles can execute:

[cols="1,1,2",options="header"]
|===
|Profile |Steps |Scope
|`graft` |`G` |A complete rooted processed document grafted into the captured host.
|`svg_cleanup` |`D -> S -> N` |Exactly one selected SVG root, including its nested SVGs.
|`graft_then_svg_cleanup` |`G -> D -> S -> N` |A captured host whose root is SVG.
|===

Appending an invalid sequence raises `ArgumentError` containing
`invalid step sequence`. Calling an incomplete prefix raises `ArgumentError`
containing `incomplete profile`. A wrong input scope raises `ArgumentError`
containing `execution-scope mismatch`. Parse errors stop execution and propagate.

=== Standoc migration boundary

Map and graft the complete prepared host once, then process the selected SVGs in
document order. Preserve the caller's sequential collision map; do not use the
batch `SvgIdDisambiguator.duplicate_ids` helper for this compatibility flow.

[source,ruby]
----
mapped = Vectory::SvgMapping.new(original_host).call.to_xml
grafted = Vectory::SvgTransform.graft_into(host_content: original_host).call(mapped)
document = Leptris::XML.parse(grafted)
collisions = {}
document.xpath("//*[local-name()='svg' and not(ancestor::*[local-name()='svg'])]").each_with_index do |svg, index|
  # Make inherited namespace bindings explicit before serializing this subtree.
  declared_prefixes = svg.namespace_definitions.map(&:prefix)
  svg.namespaces.each do |name, uri|
    prefix = name == "xmlns" ? nil : name.delete_prefix("xmlns:")
    next if declared_prefixes.include?(prefix)

    svg.add_namespace_definition(prefix, uri)
  end
  pipeline = Vectory::SvgTransform.disambiguate(index: index, duplicate_ids: collisions) >>
    Vectory::SvgTransform.suffix_classes(index: index) >>
    Vectory::SvgTransform.bind_namespaces(bind: { "xlink" => "http://www.w3.org/1999/xlink" })
  cleaned = pipeline.call(svg.to_xml)
  Leptris::XML.parse(cleaned).xpath("//*[@id]").each { |node| collisions[node["id"]] = true }
  svg.replace(cleaned)
end
----

Each pipeline retains the collision map as it existed at construction. The first
repeated root ID remains unchanged; the later one receives its positional suffix.
The selected SVG must carry its in-scope namespace declarations across the string
boundary; a declaration inherited from the host is otherwise lost by `to_xml`.
Standoc #1298 consumes `SvgIdDisambiguator` and retains its current Crass helpers.
`SvgClassSuffixer` is the canonical Vectory implementation; later adoption and
removal of the inline helpers require a separate task after a containing release.

== PNG rendering and conformance

PNG is output-only. Every vector class (`Svg`, `Emf`, `Eps`, `Ps`) exposes
`to_png(profile: {}, fonts:, fallback_fonts:)`, returning `Vectory::Png`.
The transform pipeline may produce the final SVG bytes; rendering consumes those
bytes without depending on transform pipeline classes.

[source,ruby]
----
require "vectory"
require "svgpng"

svg = Vectory::Svg.from_path("diagram.svg")
face = Svgpng::FontFace.new(bytes: File.binread("fonts/ExampleSans.ttf"),
                           source_id: "fonts/ExampleSans.ttf")
fallback = Svgpng::FontFace.new(bytes: File.binread("fonts/ExampleSymbols.ttf"),
                               source_id: "fonts/ExampleSymbols.ttf")
png = svg.to_png(profile: { width: 1200, background: "#ffffff" },
                 fonts: { "Example Sans" => [face] }, fallback_fonts: [fallback])
png.write("diagram.png")
png.warnings.each { |warning| warn warning.inspect }
----

Font families must match normalized byte-derived metadata. Multiple faces per
family support style, weight, and stretch. A cluster selects an exact-family
face with full coverage before trying fallback faces in caller order. Missing
coverage raises `Vectory::FontError`. No system fonts are searched. Text-free
SVG uses explicit `fonts: {}, fallback_fonts: []`. Ruby exposes ordered structured
warnings; the CLI emits each substitution once to stderr, naming families,
style/weight/stretch, and Unicode scalars.

`Png#content` is binary (`ASCII-8BIT`); `#mime` is `image/png`. `#width`, `#height`,
and `#size` report pixels and byte count. `#warnings` is an immutable collection.
`#write(path)` writes bytes and returns the image; `#path` and `#file_size` raise
before writing. The first no-argument `#write` creates a temporary file and later
calls reuse its path. PNG has no vector data-URI interface and is not accepted
as conversion input.

[source,sh]
----
vectory -f png -o diagram.png --width 1200 --height 800 \
  --background '#ffffff' --font 'Example Sans=fonts/ExampleSans.ttf' \
  --fallback-font 'Example Symbols=fonts/ExampleSymbols.ttf' diagram.svg
vectory -f png --scale 2 --background transparent diagram.svg
----

All PNG-only CLI flags are `--width`, `--height`, `--scale`, `--background`,
repeatable `--font FAMILY=PATH`, and repeatable `--fallback-font FAMILY=PATH`.
Other output formats reject these options. Profile keys are the corresponding
Ruby symbols: positive integer width/height, positive decimal-string scale,
and background `transparent`, `#RRGGBB`, or `#RRGGBBAA`. Scale cannot accompany
width/height. Both dimensions set an aspect-preserving centered canvas; one
derives the other. Otherwise scale multiplies intrinsic dimensions.
Intrinsic size uses both root dimensions, derives a missing dimension from a
positive `viewBox`, uses `viewBox` alone, then defaults to 300 by 150.
A missing axis without a usable `viewBox` defaults to 300 or 150; percentage
root lengths use that viewport and absolute units use 96 dpi. Dimensions round
half up with a one-pixel minimum.

Raw DTD/DOCTYPE declarations are rejected before parsing or entity expansion.
Same-document fragments and inline `data:` resources are accepted; paths,
network URLs, other non-inline references, and CSS `@import` are rejected.
There is no external-resource loader or option to enable one.

Enforceable limits: SVG 16 MiB; 64 faces; 32 MiB per font and 128 MiB total;
32768 pixels per axis; 64,000,000 pixels; checked row stride and at most
256 MiB output buffer. A synchronous native render has no safe cancellation;
use a killable isolated process for wall-clock deadlines.

`RenderProfileError`, `MalformedSvgError`, `FontError`,
`ForbiddenExternalReferenceError`, and `RenderLimitError` are Vectory conversion
errors (CLI status 4). `UnsupportedPlatformError`, `RendererLoadError`,
`NativeRenderError`, `PngEncodingError`, and filesystem `SystemCallError` are
Vectory system-call errors (CLI status 5). Success is 0; unsupported input/output
remain 2/3 and same-format vector conversion remains 7.

The seven native packages target `arm64-darwin`, `x86_64-darwin`, `x86_64-linux`,
`aarch64-linux`, `x86_64-linux-musl`, `aarch64-linux-musl`, and `x64-mingw-ucrt`.
They require no external renderer/compiler. Other platforms install the
same-version Ruby shell; requiring Vectory and non-PNG conversions still work,
but PNG requests raise `Vectory::UnsupportedPlatformError` (status 5).
Release requires the qualified seven native packages and shell together.

Byte identity requires identical SVG/font inputs, fallback order, profile, and
qualified renderer/dependency build. See
https://github.com/claricle/svgpng/blob/main/docs/decisions/svg-to-png.md[svgpng support, provenance, encoder, and release details]
and https://github.com/claricle/svgpng/blob/main/docs/goldens.md[golden compatibility].
Conformance does not prove visual fidelity, arbitrary SVG feature support, or
byte identity across renderer builds.

For development/CI, the tracked Gemfile pins test-only `png_conform` 0.1.4 to
`653abae0d16d9533a37a5d5eca40896d3b307993`; it is not a runtime dependency.
The lockfile remains ignored and untracked. After `bundle install`:

[source,ruby]
----
require "png_conform"
require "png_conform/services/validation_orchestrator"

analysis = PngConform::Services::ValidationOrchestrator.validate_file(png.path)
raise analysis.to_json unless analysis.valid?
----

`bundle exec png_conform check --format json diagram.png` validates a file from the CLI.
`bundle exec rspec spec/integration/png_conform_spec.rb` proves direct handoff of
a real written PNG plus rejection of a corrupted copy with diagnostic errors.
No conformance adapter is required.
