# 04 — Add PNG output and inputs to Vectory

## Work

This card is implemented in `claricle/vectory`; all paths are relative to that repository. Declare `spec.add_dependency "svgpng", "~> 0.1.0"` in `vectory.gemspec`, following the existing sibling-gem dependency direction used for `emfsvg` and `postsvg`. The initial integration artifact is exactly `svgpng` 0.1.0, and the pessimistic constraint admits compatible 0.1.x fixes but not a 0.2 contract/golden change. Vectory calls only the public `Svgpng` byte/options boundary and lazily loads it on PNG projection. RubyGems selects a native 0.1.0 package on the seven supported targets or the same-version `ruby` shell elsewhere, so dependency installation and existing non-PNG startup remain available on unsupported platforms; a PNG request through the shell raises the mapped unsupported-platform error.

Do not start Vectory integration merely because source exists. Cards 01–03 must have finalized the public API/error contract and produced a cleanly installable, unpublished `pkg/svgpng-0.1.0-<development-platform>.gem` containing the native artifact for Vectory's development/CI platform. Record its filename, platform, SHA-256, and passing clean-install/require/minimal-render smoke command in the Card 04 handoff, and use a Bundler local source override that is not committed. That local package is sufficient to develop and review this card. Do not merge or release the Vectory dependency until Card 05 has passed on all seven native targets and published the exact checksummed seven native packages plus the `ruby` shell package as one 0.1.0 set to Vectory's configured gem source.

Add `lib/vectory/png.rb` and autoload it from `lib/vectory.rb`. Move the complete generic file lifecycle from `lib/vectory/vector.rb` to `lib/vectory/image.rb`: `from_path`, `initial_path`, `size`, `file_size`, `write`, written `path`, and temporary-path ownership. Keep vector-only MIME/data-URI and projection behavior in `Vector`. Preserve the current semantics exactly: `initial_path` records a source path; `path` and `file_size` still raise before the first write; a no-argument first write uses a temporary output rather than overwriting the source; later no-argument writes reuse the written path; and an explicit output path is retained. Exercise the shared contract against both an existing Vector type and `Png`.

Add a project-owned raw-input guard in the proposed `lib/vectory/svg_input_policy.rb` and call it from `Vectory::Svg#content=` before the existing `Leptris::XML.parse(content).root` call. It tokenizes the raw bytes without entity expansion and rejects any XML `DOCTYPE` declaration as `Vectory::ForbiddenExternalReferenceError`; `DOCTYPE` text inside comments or CDATA is not a match. Because both inherited `Svg.from_content` and `Vector.from_path` construct `Svg` through `content=`, this single guard covers direct content, the one declared source-file read, delegated conversions, and CLI input before Leptris can discard the declaration or serialize entity text. Tests must prove that `from_content`, `from_path`, and CLI inputs return the same safe error without opening any secondary file or socket; `from_path` may read only its explicitly supplied source path.

`Vectory::Png < Vectory::Image` exposes binary content, `image/png`, `.png`, dimensions through the existing `image_size` dependency, structured renderer warnings, and the shared write lifecycle. Add `Vectory::Svg#to_png(profile: {}, fonts:, fallback_fonts:)` in `lib/vectory/svg.rb`; it passes `Svg#content`—the serialized SVG produced by the existing `document.to_xml` path—and explicit inputs to `Svgpng.render`, then maps the result to `Vectory::Png` without losing warning order. This work does not introduce XML canonicalization or accept a resource directory, map, or loader.

Add matching `to_png(profile: {}, fonts:, fallback_fonts:)` projections to `Vectory::Emf`, `Vectory::Eps`, and `Vectory::Ps`. Each delegates through its existing `to_svg` method and then calls `Svg#to_png`, forwarding the keyword values unchanged and returning the resulting `Vectory::Png`. Conversion failures from the existing EMF/PostScript-to-SVG stage retain their current Vectory error behavior; `Svgpng` warnings and failures from the second stage propagate through the same result and error mapping as a direct SVG render. This preserves the CLI's object-level `public_send("to_#{format}")` dispatch and makes PNG output available for every currently supported input format.

Wrap every public `Svgpng::Error` before it reaches the CLI. Map profile, malformed-input, font, forbidden-reference, and pre-allocation-limit categories to named Vectory subclasses of `Vectory::ConversionError` (exit 4); the raw-input DTD guard raises the same named forbidden-reference subclass before `Svgpng` is called. Map unsupported-platform, loader, native-render, and PNG-encoder categories to named subclasses of `Vectory::SystemCallError` (exit 5), retaining the original exception as cause. Map font option file-read failures to `Vectory::SystemCallError`. Change the CLI's exact-class status lookup to ancestry-aware `is_a?` matching so these subclasses use the established statuses; never allow a raw `Svgpng` or `LoadError` backtrace through the normal command path.

Extend `lib/vectory/cli.rb` with repeatable `--font FAMILY=PATH` and ordered repeatable `--fallback-font FAMILY=PATH` options. Multiple `--font` entries for one family supply distinct style/weight/stretch faces; the family token on either font option is validated against the file's normalized metadata. Read each path as binary and construct `Svgpng::FontFace` values. Add PNG-only `--width PIXELS`, `--height PIXELS`, `--scale NUMBER`, and `--background transparent|#RRGGBB|#RRGGBBAA` profile options, using Card 01's precedence rules. Reject duplicate face metadata, malformed assignments, and use of these options with non-PNG output as conversion errors. Change projection dispatch so PNG receives these keywords while existing projections remain zero-argument calls. Print structured substitution warnings to stderr in renderer order, once each, without contaminating PNG stdout/file bytes. A forbidden external SVG reference follows the conversion-error path; the CLI offers no flag that can grant filesystem or network access.

Add focused coverage in `spec/vectory/png_spec.rb`, `spec/vectory/svg_input_policy_spec.rb`, `spec/vectory/svg_spec.rb`, `spec/vectory/emf_spec.rb`, `spec/vectory/eps_spec.rb`, `spec/vectory/ps_spec.rb`, `spec/vectory/vector_spec.rb`, and `spec/vectory/cli_spec.rb`. Cover successful PNG output from SVG, EMF, EPS, and PS inputs. At the projection boundary, assert unchanged forwarding of profile, font, and fallback values plus ordered warning and mapped-error propagation for each delegated input; at the CLI boundary, exercise the full successful input matrix and use direct SVG and delegated EMF cases to prove option, warning, conversion-error, and system-error behavior end to end. Add DTD/external-entity cases through `Svg.from_content`, `Svg.from_path`, and the CLI, instrumenting secondary file and socket access and asserting exit 4. Also include malformed/profile/font/forbidden-reference/limit exit-4 cases, platform/loader/native/encoder exit-5 cases, and non-PNG option rejection. In an unsupported-platform package-resolution job, prove Bundler installs the `ruby` shell, a non-PNG Vectory conversion still runs, and a PNG request reaches the mapped exit-5 unsupported-platform error. Update the README's pure-Ruby/external-binary description to explain the native and shell `svgpng` packages accurately.

## Done when

- `Vectory::Svg#to_png` passes serialized `Svg#content` without adding an XML-canonicalization step and returns a `Vectory::Png` whose bytes, MIME type, extension, dimensions, size, warnings, and write behavior match the public contract.
- `vectory.gemspec` declares runtime dependency `svgpng ~> 0.1.0`, and the handoff records the unpublished 0.1.0 development-platform package filename, platform, SHA-256, and passing clean-install/require/render smoke check used for development and review.
- Card 04 remains unmerged until Card 05 publishes the exact tested seven native packages and `ruby` shell package; supported Bundler resolution selects the native gem, while unsupported resolution installs the shell, preserves non-PNG conversion, and maps a PNG request to exit 5.
- `Vectory::Emf#to_png`, `Vectory::Eps#to_png`, and `Vectory::Ps#to_png` delegate through `to_svg`, forward profile, font, and fallback inputs unchanged, and preserve ordered warnings and mapped failures from `Svg#to_png`.
- Exact fonts, ordered fallbacks, and render-profile options pass to `Svgpng` with deterministic warning presentation and no resource-injection parameter.
- `Image` owns `initial_path`, `from_path`, `size`, `file_size`, `write`, and `path`, while existing pre-write, source-path, explicit-write, and repeated-write semantics pass for Vector and PNG values.
- The CLI exposes the specified repeatable font/fallback and PNG profile flags, renders PNG successfully from SVG, EMF, EPS, and PS, rejects invalid or non-PNG uses, and has no external-resource option.
- Direct-SVG and delegated-EMF CLI examples prove profile/font/fallback forwarding, ordered-warning presentation, and exit-4/exit-5 error propagation; projection specs prove the same forwarding contract for EPS and PS.
- Every `Svgpng` error category is wrapped into an ancestry-mapped Vectory exit-4 or exit-5 error, with focused CLI coverage for each category and no raw native exception.
- DTD-bearing raw SVG is rejected before Leptris parsing through `Svg.from_content`, `Svg.from_path`, and the CLI, with no secondary filesystem or network access and the declared source file as the only permitted read.
- PNG remains output-only and no raster input, mutation, sniffing, `FileMagic`, or data-URI parsing API is introduced.
- Gem metadata and README identify `svgpng`, the seven supported platforms, prebuilt-artifact behavior, and unsupported-platform failure.
